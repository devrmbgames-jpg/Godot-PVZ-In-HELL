## Историческая ручная приёмка до автоматической регистрации

- [x] Утром в терминале видны поступившие коробки до сканирования: «Без номера», описание, дата поступления; номер 000 и дата регистрации день 0 не показываются.
- [x] После сканирования существующая строка получает номер выдачи; второй строки той же посылки нет.
- [x] До прихода клиента доступна «Потеряли»; «Забрали» и «Отказались» доступны после начала визита.
- [x] Уничтожить незарегистрированную коробку: запись остаётся, потеря автоматически не объявляется. Заявить её вручную, открыть архив и проверить сохранённую отметку.
- [x] Оставить поступившую коробку без регистрации до истечения срока: следующим утром показывается просрочка и её штраф; коробка остаётся физическим предметом. Повторное открытие терминала и ожидание не повторяют штраф.
- [x] Поздно зарегистрировать сохранившуюся коробку: получатель может прийти и получить её по обычным правилам.
- [x] Проверить читаемость длинного статуса «ПРОСРОЧЕНА РЕГИСТРАЦИЯ», кнопок и даты при используемом разрешении экрана.

Визуальная проверка ещё не выполнялась. Версия сохранения 3, полный перезапуск большого сценария и Windows QA-сборка относятся к последующим задачам интеграции.

## Текущий контракт автоматической регистрации — manual NOT_RUN

Новые сценарии [задачи](../../.agents/tasks/completed/package_automatic_arrival_registration.md) заменяют прежний scanner-first flow; общая приёмка старого checkpoint их не покрывает.

- [ ] Без сканера строка реально выгруженной коробки показывает `№001` и даты поступления/регистрации; второй строки при чтении сканером нет.
- [ ] Неразмещённая из-за препятствия коробка не создаёт фиктивную строку/номер.
- [ ] Первый и повторный scan, в том числе следующим днём, показывают прежний номер и не меняют даты.
- [ ] Несканированная выгруженная коробка доступна получателю; отсутствие scan не создаёт просрочку или штраф.
- [ ] После сна/загрузки номера и история сохраняются; номер освобождается только подтверждённым уходом коробки со склада.

Строки без номера и прежний overdue settlement сохраняются для старой отсутствующей/закрытой истории и изолированных fixtures. Restore регистрирует только существующие действующие поступления; уже зафиксированные штрафы не отменяет. Новая визуальная приёмка не выполнялась.
