# Проверки игры для игроков

Здесь находятся ожидающие ручные проверки. Реализация механик ведётся в `agent_tasks/`; результат игрового теста записывается в соответствующий сценарий ниже. Ни одна проверка не считается пройденной только из-за переноса или автоматических тестов.

## Как начать

1. Запустите `.export/LATEST.cmd` — [инструкция к Windows-билдам](../.export/README.md). Его версия записана в `build_info.json` рядом с EXE. QA-сохранения отделены от прогресса редактора/основной игры.
2. Выберите сценарий с состоянием «Готово к проверке». Следуйте экранным подсказкам действий. В текущих сборках основная сцена — `main_level`; простая тестовая сцена пока ожидает реализации.
3. Запишите дату, версию сборки, результат и замечания в конце выбранного сценария. При ошибке укажите шаги воспроизведения и ожидаемое/фактическое поведение.

«Готово к проверке» означает, что сценарий можно запускать; успешное прохождение ещё не подтверждено. Для полного дня желательно начать новый QA-профиль: сохраните существующие QA-сохранения перед его сбросом. Отдельные ветви исходов проверяйте в отдельных проходах.

Если механика пока не готова, её пункты не закрывайте. После исправления разработчик обновляет готовность и сборку; повторный результат записывает игрок.

## Формат результата

В каждом сценарии есть место для записи: дата, сборка/коммит, мышь/клавиатура или геймпад, пройденные пункты, проблемы и шаги воспроизведения. Скриншот/видео можно приложить при необходимости, но для отчёта достаточно описания.

Проверки R12–R23, включая ручные остатки R22.5, перенесены из блоков Owner QA общих задач. Уже подтверждённое владельцем прохождение R11.1 остаётся историей в исходной задаче; его действия повторяются в полном дне как регрессия.
