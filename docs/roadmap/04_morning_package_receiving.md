# ТЗ 04 — Утренняя приемка посылок

## Цель

Создать первый полный рабочий процесс ПВЗ.

## Поставка

В начале Morning в зоне приемки появляются 6–10 физических Package.

Каждая имеет:

- внутренний ID;
- будущий номер отправления;
- краткое описание содержимого;
- Customer/recipient;
- PackageTags;
- параметры повреждения;
- состояние регистрации.

## PackageTags

Минимум:

- Normal;
- Fragile;
- Heavy;
- Liquid.

Теги могут сочетаться:

```text
Heavy + Fragile
Liquid + Fragile
Normal
```

## Начальное состояние

Новая посылка:

```text
Unregistered
NotScanned
Closed
Undamaged
```

До регистрации она не может быть корректно выдана клиенту.

## Долгоживущие и возвратные Package

Package не привязана к одному рабочему дню.

Если Customer еще не пришел, Package остается физически на складе через Night/следующие Morning и продолжает занимать свой регистрационный номер.

Если Customer добровольно или принудительно отказался от Package, Player может сдать её через утренний return flow.

Утренний возврат:

- завершает складской lifecycle Package только после успешного приема возврата;
- освобождает регистрационный номер после commit результата;
- не отменяет уже созданную Complaint или примененный штраф;
- не должен автоматически исчезать/телепортировать Package до физического/логического подтверждения возврата.

Если добровольно отказную Package Player не возвращает и оставляет себе, применяется buyout/settlement из ТЗ 07.

## Сортировка

После регистрации игрок физически переносит коробку и сам выбирает место хранения.

Игра не должна автоматически ставить Package на правильную Shelf.

## Допустимые ошибки

Игрок может:

- положить не туда;
- забыть номер;
- оставить в проходе;
- повредить;
- вскрыть;
- потерять;
- посмтроить из посылок и обьектов башню по среди комнаты.

Это часть gameplay, а не ошибка системы.

## Критерий готовности

Morning создает разные физические коробки. Игрок может зарегистрировать и разложить их без автоматической коррекции своей организации.
