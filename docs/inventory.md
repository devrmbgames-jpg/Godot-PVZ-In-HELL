# Small inventory / consumables

`C_InventoryItem.definition + quantity` is the item state; `R_OwnedBy` points from item to the sole Entity with `C_Inventory`. No UI or owner array is authority. Packages and grabbable physical objects remain in the world/physical slots. Canonical `DEF_InventoryItem` Resources define compatibility and maximum stack; `C_Inventory.maximum_stacks` bounds capacity.

`InventoryService.transfer(item, destination, expected_owner = null)` transfers the whole quantity or rejects before mutation. Null expected owner is pickup/grant; Trader/container/loot passes its current owner. Compatible existing stacks fill first; remaining quantity retains the incoming Entity. Fully absorbed/consumed stacks are removed. Ownership is registered state independent of enabled status; disabled stored items count capacity but action eligibility requires enabled/available actors/items.

`use(owner, item, target = null)` invokes Hunger Food, a normal HEAL DamageRequest, or `PackageProtectionService.apply` using R08 impact protection. Quantity decrements only after a successful immediate effect or matching DamageResult with positive healing. Unique per-owner use serials reject old/repeated results; the owner lock prevents reentrant transfer/use while an effect is pending. Inventory does not write Health or duplicate impact formulas. Full health/zero Hunger/equal-or-stronger protection retains items. Healing returns request acceptance; the observer owns subsequent commit/rejection.

`O_InventoryEffect` and `O_InventoryLifecycle` must be registered. Owner removal/disable/death deletes stored items. Item removal/disable cancels pending-use locks. Direct Entity relationship-removal listeners are bound idempotently (including existing items), because GECS disconnects its World listener on item disable. Transfer state suppresses intentional-detachment cleanup. Runtime use/transfer flags and serials are transient, and must reset on load; definitions/quantity and owner identity are the R21 persistence surface.

Main level offers Food/Med/Wrap on the Terminal desk. E pickups use the ordinary resolver; Tab opens a derived modal view. It captures input through InteractionControlFocus and keeps world time running. Wrap uses the package aimed at before opening, revalidated by the real ray on each use. Closing releases only its capture token. HUD exposes quantities, readiness and current task. Rendered readability/gamepad/balance remain owner QA.
