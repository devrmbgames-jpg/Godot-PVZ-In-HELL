# Короткая шпаргалка по запросам к ИИ

## Главное правило

Давай агенту **одну конкретную цель за раз**.

Пиши:

```text
Задача:
<что именно сделать>

Scope:
<какие системы/файлы можно трогать>

Не делать:
<что сейчас не относится к задаче>

Готово когда:
<1–3 проверяемых результата>
```

Не проси сразу: «изучи весь проект и реализуй всю систему».

## Баг

```text
Исправь <симптом>.

Ошибка/поведение:
<лог или краткое описание>

Начни с:
<файл / класс / система, если известны>

Не делай широкий рефакторинг.
Сначала найди причину, затем исправь минимальный scope.
```

## Фича

```text
Реализуй только <один этап фичи>.

Контракт:
<главные правила>

Пока не делай:
<UI / Push / Inventory / другое>

Если задача длинная/прерываемая — обнови CURRENT_WORK.md с точным следующим шагом. Для обычной задачи checkpoint не создавай.
```

## Большой рефакторинг

Не:

```text
Сделай полностью R06.1.
```

Лучше:

```text
Этап 1:
Спроектируй только data model <системы>.
Код других частей пока не меняй.

После этого остановись на проверяемом результате.
```

Следующим запросом — следующий этап.

## Что помогает экономить токены

- Не проси «изучить весь проект».
- Ссылайся на конкретное ТЗ/agent task.
- Указывай, что уже решено и не нужно пересматривать.
- Ограничивай scope.
- Большие задачи дели на этапы.
- Между завершёнными этапами агент должен делать **локальный git commit**.
- Для продолжения длинной незавершённой задачи пиши: **«Продолжай с CURRENT_WORK.md»**. Для новой задачи checkpoint читать не нужно.
- Если архитектура уже утверждена, прямо пиши: **«Архитектуру не пересматривай»**.


## Для roadmap / agent_tasks

Достаточно:

```text
Начни RXX из agent_tasks.
Работай по AGENTS.md.
Делай локальный commit после каждого законченного этапа.
```

Продолжение:

```text
Продолжай RXX с CURRENT_WORK.md.
Архитектуру без причины не пересматривай.
После законченного этапа сделай локальный commit.
```
