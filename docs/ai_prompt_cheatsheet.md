# Шпаргалка: Prompt → Plan → Goal

Обычно достаточно дать агенту цель, симптом/контракт и стартовый файл, если он известен. Не нужно перечислять все проектные документы.

## Маленький баг

```text
Исправь <симптом>.

Ошибка:
<короткий лог>

Начни с:
<файл / класс, если известен>

Не делай несвязанный refactor.
```

Для локального исправления отдельный task-файл не нужен.

## Обычная задача

```text
Реализуй <результат>.

Ограничения:
- ...
- ...

Начни с <файл/подсистема>, если известно.
Сначала составь Plan, затем после проверки плана выполняй по Goal.
```

Plan отвечает за маршрут выполнения. Goal фиксирует, что должно быть истинно в конце и как проверить завершение.

## Большая / межсессионная Feature

Если работа должна пережить текущий thread/session, укажи или создай один durable task:

```text
Продолжай agent_tasks/R35_<name>.md.
Используй его только как durable checkpoint; текущий execution веди через Plan + Goal.
```

Не создавать параллельно `CURRENT_WORK`, queue/status index или отдельный history-файл.

## Экономия контекста

- одна конкретная цель за раз;
- точный путь/символ лучше «изучи весь проект»;
- не просить заранее читать roadmap, architecture и все skills;
- MCP использовать для live scene/editor/runtime context, когда это реально помогает;
- не выгружать весь SceneTree/log без необходимости;
- не запускать broad tests после каждой мелкой правки;
- для отдельного review достаточно попросить focused review текущего diff.
