# Короткая шпаргалка по запросам к ИИ

Главное: давай Astra одну конкретную цель и не проси заранее изучать весь проект.

## Баг

```text
Исправь <симптом>.

Ошибка:
<короткий лог>

Начни с:
<файл / класс / система, если известны>

Не делай широкий рефакторинг.
```

## Фича

```text
Реализуй <один законченный этап>.

Контракт:
<2–5 главных правил>

Не делать:
<соседние задачи>

Готово когда:
<1–3 проверяемых результата>
```

## Большая задача

Укажи конкретный `agent_tasks/Rxx` или milestone-файл. Не пиши «изучи весь проект».

Если работа прерывается, попроси обновить `CURRENT_WORK.md`. Если задача завершена или новая — checkpoint читать не нужно.

Полезные фразы:
- «Архитектуру не пересматривай без конкретной причины».
- «Начни с указанных файлов, остальные открывай только по зависимостям».
- «После законченного этапа сделай локальный commit».
- «Тесты запускай только по правилам AGENTS.md».

## Экономия токенов

- одна цель за раз;
- точный файл/символ лучше широкого описания;
- не дублируй уже утверждённый контракт в каждом запросе;
- большие refactor-задачи дели на milestone-файлы;
- не проси читать `CONTEXT.md`, `PROJECT_INDEX.md` и roadmap одновременно;
- не проси «проверить всё» без явного scope;
- для обычного bugfix достаточно ошибки + ожидаемого поведения + стартового файла, если он известен.
