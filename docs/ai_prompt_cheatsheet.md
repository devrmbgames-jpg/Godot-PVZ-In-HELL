# Короткая шпаргалка по запросам к ИИ

Обычно достаточно дать **цель + симптом/контракт + стартовый файл**, если он известен. Не нужно вручную объяснять агенту весь workflow: `develop` сам определит Fix / Task / Feature после исследования.

## Баг

```text
Исправь <симптом>.

Ошибка:
<короткий лог>

Начни с:
<файл / класс, если известен>

Не делай несвязанный refactor.
```

## Фича

```text
Реализуй <результат>.

Главные ограничения:
- ...
- ...

Начни с <файл/подсистема>, если известно.
```

Агент сам решит, достаточно ли обычного Fix/Task workflow или нужен durable Feature task.

## Продолжить существующую задачу

Укажи точный task/router:

```text
Продолжай agent_tasks/roadmap_11_1_extended_interactions_and_arrangement.md
```

Агент должен прочитать его authoritative `Task state`, текущий milestone и только необходимые ссылки. Не нужно отдельно пересказывать `CURRENT_WORK.md`.

Если пользователь говорит просто «продолжай текущую работу», тогда используется `CURRENT_WORK.md`.

## Большая новая задача

Если task/router уже существует — используй его, не проси создать второй план.

Если не существует, достаточно описать цель и ограничения. Для Feature-level работы агент сам создаст durable state по правилам `AGENTS.md`.

## Экономия токенов

- одна конкретная цель за раз;
- точный путь/символ лучше «изучи весь проект»;
- не проси одновременно читать `CONTEXT.md`, `PROJECT_INDEX.md`, roadmap и все skills;
- не копируй в промпт большой контракт, если он уже лежит в конкретном task/doc;
- не проси тесты после каждого мелкого коммита;
- для review можно попросить «проведи independent review текущего diff» — findings будут triaged автоматически.
