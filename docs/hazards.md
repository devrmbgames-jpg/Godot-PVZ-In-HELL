# Автономные опасные эффекты (R09)

`ToxicArea` и `Explosion` — отдельные Entity. Посылка, бочка, клиент или ловушка только инициируют появление эффекта; урон и время жизни принадлежат самому эффекту. Единственный обработчик HP — `O_Damage`.

## Подключение к новому объекту

1. Объект должен быть GECS Entity на пространственном узле, зарегистрированном в World.
2. Добавить в `component_resources` компонент `C_HazardEmitter`.
3. Назначить ему `definition`: собственный ресурс `DEF_ToxicArea` или `DEF_Explosion`. Готовые образцы находятся в `content/definitions/gameplay/hazards/`.
4. Для взрыва при исчерпании HP добавить `C_Health` и оставить триггер `Health depleted`. Для ручной активации вызвать `HazardEmitter.activate(owner, instigator)`; маска автоматических триггеров её не ограничивает.

`one_shot = true` защищает инициатора от повторного запуска. У повторяемого инициатора каждый запуск увеличивает `sequence`. Фабрика дополнительно запоминает `request_id` на время существования World: повторная доставка того же запроса не создаёт второй эффект, даже после его удаления/reset. Разные объекты не делят cooldown.

Главная сцена уже регистрирует необходимые обработчики. В другой сцене нужны `O_HazardSpawn`, `O_HazardEmitter`, `O_ToxicAreaSetup`, `O_ExplosionSetup`, `O_HazardReset`, `O_Damage` и системы `S_HazardFollow`, `S_ToxicArea`, `S_Explosion`, `S_HazardLifetime`. Системы должны обрабатываться в одной группе на физическом шаге, с обычным GECS flush после каждой системы. `deps()` ставит следование до воздействия, а удаление — после него.

## Прямой запрос без объекта-инициатора

```gdscript
var request: HazardSpawnRequest = HazardSpawnRequest.new()
request.request_id = "trap-17:activation-3"
request.origin_id = "trap-17"
request.definition = preload("res://content/definitions/gameplay/hazards/parcel_blast.tres")
request.world_pose = Transform3D(Basis.IDENTITY, Vector3(2, 1, 3))
HazardSpawnService.submit(request)
```

`submit()` возвращает принятие корректного запроса на канал событий, а не число созданных объектов. Факт создания публикуется как `HazardSpawnResult.EVENT`. Настройка формы/представления выполняется на этом событии, после полной регистрации компонентов Entity. Созданный prefab должен иметь нефизический Node3D-корень с `E_ToxicArea`/`E_Explosion` и соответствующим компонентом эффекта. Запросы отправляют после регистрации фабрики в World.

Ресурс содержит prefab и конечное `lifetime_seconds`. Он считается неизменяемым после отправки. При прямом запросе `ownership`/`owner_loss` задаются в запросе явно; `HazardEmitter` копирует их из ресурса автоматически. `origin` и `instigator` необязательны. Для атрибуции, переживающей удаление объектов, служат `origin_id` и `instigator_id`.

## Поведение

| Эффект | Контракт |
| --- | --- |
| ToxicArea | Сфера `Area3D`, собственный таймер. Первый урон через полный `tick_seconds`; пропущенные интервалы объединяются в один запрос на получателя. По умолчанию нужны `C_Health` + `C_Living`; `living_only = false` допускает остальные объекты с HP. |
| Explosion | Один расчёт на физическом шаге. Вес: `(1 - distance / radius) ^ falloff_power`, обрезанный по радиусу. Расстояние берётся до центра ближайшей физической формы цели. Один raycast на Entity/самостоятельное тело; препятствие полностью блокирует HP и импульс. По умолчанию препятствия — слой Terrain. |
| Импульс | `apply_central_impulse`, без присваивания скорости. Работает и для обычных RigidBody3D без GECS/HP; замороженные тела не толкаются. Если несколько физических тел принадлежат одной Entity, MVP выбирает ближайшее. |

`maximum_targets` ограничивает число результатов физического запроса взрыва (включая формы и препятствия). В плотных сценах его нужно увеличить. Коллайдеры живого инициатора исключаются из LOS, чтобы корпус не перекрывал собственный взрыв. Частичное укрытие и расчёт по поверхности крупных тел в MVP отсутствуют. Перекрытия Area3D обновляются физическим движком, поэтому перемещённая привязанная зона использует результаты последнего физического шага.

Урон всегда имеет `source = hazard Entity`; живой `instigator` и стабильные идентификаторы передаются отдельно. `C_NoDamage` инициатора копируется на эффект при создании и продолжает блокировать HP после удаления инициатора. Он не отменяет физический импульс — это действующий контракт запрета исходящего урона. Цепные реакции проходят через обычный damage/depletion и отдельный one-shot каждого следующего инициатора.

## Посылки

`O_PackageHazardSetup` только подбирает ресурс и триггеры. `O_PackageHazard` переводит lifecycle-события в обычную активацию emitter. По умолчанию Toxic запускается от `Leaking` или `Destroyed` один раз; Explosive — от `Destroyed`. `Opened` включается только явно в `DEF_Package.hazard_triggers`. `hazard_effect` позволяет заменить ресурс; заранее заданный `C_HazardEmitter` позволяет настроить объект непосредственно. Внутри обработки эффектов нет зависимости от Package.

## Время жизни, следование и будущий reset

- `Independent`: эффект остаётся в мире после удаления инициатора.
- `FollowOrigin`: компонент `C_HazardFollow` перемещает только нефизический корень эффекта. При потере/отключении владельца `Detach` оставляет эффект на последней позиции, `Despawn` удаляет его.
- Истечение TTL или отключение самого эффекта удаляет регистрацию и узлы; удаление через `World.remove_entity()` также освобождает сцену. У взрыва отсчёт TTL начинается с разрешения, чтобы короткий цепной эффект не исчез до первого хода своей системы.
- `persistent` исключает эффект из обычного reset, но не отменяет TTL.

Будущий переход ночи может отправить:

```gdscript
var reset: HazardResetRequest = HazardResetRequest.new()
ECS.world.emit_event(HazardResetRequest.EVENT, null, reset)
```

`include_persistent = true` удаляет все эффекты. R09 не подключает reset к текущему дню и не реализует сохранение R21. Будущий save должен сохранять остаток TTL, интервал токсина, состояние разрешённого взрыва, идентификаторы/атрибуцию, producer `fired`/`sequence`, follow-policy и журнал уже принятых request ID (либо восстанавливать эквивалентную защиту от повторов).

## Проверка пользователем

```powershell
.\utils\run_smoke.ps1 -Name hazards
```

`hazards_smoke.tscn` создаёт отдельный World: взрывные объекты без `C_Package`, привязанный эффект условного клиента, несколько зон, получателей с/без HP и стену. Проверяет дедупликацию, интервал, eligibility, удаление инициатора, follow-policy, reset, цепную реакцию, LOS, затухание, импульс и запрет исходящего урона. Небольшой отдельный фрагмент проверяет адаптер `Leaking → Destroyed`.

**NOT RUN — проверку Godot/GUT/smoke и визуальную приёмку выполняет пользователь.** Агент проверяет только структуру, форматирование, lint, синтаксис PowerShell и diff. Простые зелёная зона и оранжевая вспышка показывают радиус; их читаемость и силу разбрасывания нужно оценить в игре. Инструкция запуска и расположение журналов: [smoke_runner.md](smoke_runner.md).
