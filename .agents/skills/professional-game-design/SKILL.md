# Professional game design

Design from the intended player experience backward.

A feature is justified by the decisions, learning, expression, tension, or feedback it creates—not by implementation novelty.

## Workflow

1. State player fantasy and 2–4 design pillars.
2. Define the short loop: action -> feedback -> consequence/reward -> next decision.
3. Identify meaningful decisions: information, options, tradeoff, consequence, skill expression.
4. Prototype feel before content volume.
5. Teach -> practice -> test -> combine.
6. Make tunables data-driven.
7. Playtest a hypothesis.
8. Cut/simplify features that do not reinforce pillars.

## System checks

- Prefer few interacting rules over many isolated mechanics.
- Preserve player agency; avoid false choices and universal optimal options.
- Use randomness to create adaptation, not erase causality.
- Failure should teach what to change.
- Progression should add decisions/capabilities, not only larger numbers.
- Persistent resources need intentional sources, sinks, pacing, and anti-inflation reasoning.
- RPG stats should support build diversity and avoid a universally dominant path.
- Rewards should support the core loop and player trust.

## Game feel

- input response first;
- animation/audio/VFX/camera feedback second;
- stronger feedback for more important events;
- quickly return to neutral;
- do not let feedback corrupt simulation or block essential input;
- provide reduced-motion/flashing options when effects are strong.

## Level/encounter design

- Derive spaces from actual movement/camera/combat metrics.
- Block out/playtest before art dressing.
- Keep a readable critical path plus optional discovery.
- Alternate tension and recovery.
- Guide with landmarks/light/composition/affordances before excessive UI arrows.
- Required challenges get safety margin; precision limits are for optional mastery.

## Review output

When evaluating a mechanic, return:
- intended experience;
- decision/skill it creates;
- risks/failure modes;
- smallest prototype;
- measurable playtest questions;
- tunable parameters.

Separate design goals, hypotheses, and observed evidence.
