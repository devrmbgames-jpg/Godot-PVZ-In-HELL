## Task state

### Goal / acceptance

- Имя говорящего НПЦ/клиента подставляется из актуальной личности, а не жёстко прописывается как «Клиент», «Карга» или другое имя в реплике.
- Все комментарии `content/ui/npc_dialogue_context.gd` — на русском, с понятным назначением методов и условиями результата; отдельно объяснить `holds_grudge()`.
- Дать авторам ровно пять новых операций коллекции: `set_tag(tag_name)`, `get_tag(tag_name) -> bool`, `set_val(value_name, value)`, `get_val(value_name) -> Variant`, `add_val(value_name, value)`.
- `val` может быть любым Variant; `add_val()` работает только с `int`/`float`. Отсутствующий `get_val()` возвращает `null` и **не создаёт переменную**.
- Память встреч/накопленных действий принадлежит конкретному НПЦ, общая для его уличного и клиентского разговора; сохраняется между разговорами, днями и загрузкой игры.
- Коллекция остаётся простой: не добавлять отдельный метод ctx для каждого авторского флага/счётчика и не превращать её в новую систему квестов.

- `content/ui/customer_dialogue_panel.gd` показывает `DialogueLine.character`; общая панель уже получает `{"ctx": session_context}`. Не требуется подменять владельца UI или внедрять пример balloon аддона.
- Уличный ctx уже имеет `speaker_name()`, возвращающий `NpcRecord.display_name`; часть приветствий уже использует `{{ctx.speaker_name()}}`.
- В `content/domains/npc/dialogue/archetypes/hag/variant_a.dialogue` подтверждены статические «Клиент: Заказ №…» и «Карга: Правду проще всего спрятать…». Такие заголовки встречаются и у других архетипов.
- Установленный Dialogue Manager 4.1.0 поддерживает подстановки в имени говорящего (`character_replacements` в compiler/runtime). Использовать этот существующий механизм, аддон не менять.
- `NpcDialogueService.has_grudge_against()` → `NpcGrudgeRules.remembers_offender()`: личная обида выводится из сохранённых социальных инцидентов и черты злопамятности.

- `SaveDataCodec` использует закрытый контракт полей `NpcRecord`; сохранение новых коллекций требует явного включения в этот контракт и snapshot validation.

## Русские комментарии ctx

- Перевести doc-комментарии, обычные комментарии и авторские названия регионов в указанном файле; публичные имена методов/классов/сигналов сохраняются.
- Комментарий объясняет действие или чтение, условия `true`/`false`, важный побочный эффект и жизненный цикл, если он есть; не ограничиваться буквальным переводом названия.
- Для `holds_grudge()`: «Проверяет, помнит ли этот НПЦ с чертой злопамятности личную обиду на текущего игрока. Читает сохранённые инциденты; отношение и бой не изменяет».
- Дополнить смысл: учитываются личные угрозы/ложь/нарушенное обещание/нападение и другие обиды по `NpcGrudgeRules`; увиденный вред другому НПЦ сам по себе не считается личной обидой. Невалидный ctx/отсутствие подходящей памяти дают `false`.
- Для новых пяти методов явно описать отсутствующий ключ, сохраняемый тип и правила числового сложения.

## Контракт простой коллекции

| Метод | Поведение |
| --- | --- |
| `set_tag(tag_name)` | Установить авторский флаг в `true`; повторный вызов не меняет результат. |
| `get_tag(tag_name) -> bool` | Вернуть флаг; для отсутствующего ключа `false`, без создания записи. |
| `set_val(value_name, value)` | Создать/заменить значение произвольного Variant-типа, включая явный `null`; не приводить его автоматически к строке/числу. |
| `get_val(value_name) -> Variant` | Вернуть хранимое значение с его типом; для отсутствующего ключа `null`, без создания записи. Второго аргумента нет. |
| `add_val(value_name, value)` | При числовых сохранённом значении и приращении сложить их. Отсутствующий счётчик начать с числового нуля и создать результат. |

- `add_val()` принимает только `int`/`float`; строки не конкатенируются, `bool` не считается числом. Для существующего нечислового значения, в том числе явного `null`, операция ничего не меняет и даёт понятную диагностику автору.
- Сохранять нормальную числовую семантику: int + int → int, наличие float → float; отрицательное приращение допустимо. `add_val()` намеренно изменяет счётчик при каждом новом авторском вызове.
- Ключи — стабильные авторские имена, а не локализованные реплики. Теги и значения — отдельные пространства; авторский ключ не переопределяет метод ctx или типизированную игровую память.
- Не добавлять `visited()`, `set_visited()`, `money_given()` и подобные обёртки над каждым новым ключом. Использование общего API не требует регистрации отдельной GDScript-функции.
- Предикаты/getters остаются чтением: просмотр условия не создаёт персонажа, коллекцию в сохранении, запись ключа или побочный игровой эффект.
- Пример с деньгами считает фактически переданную сумму. Списание монет выполняет экономический владелец; прибавлять счётчик только после успеха. `cost_mone` из грубого примера не вводить как опечаточный alias или обход экономики.

## Владение и сохранение

- Хранить коллекцию за постоянной личностью `NpcRecord`/`npc_id`; для привязки к участнику использовать существующий устойчивый actor ID, где этого требует личная память. Не ключевать по имени, архетипу, NodePath, instance ID, visit ID или экземпляру ctx.
- Context — тонкий адаптер чтения/записи через владельца NPC-данных. Закрытие UI, новый заказ, смена street/service, день, сон и пересоздание тела не очищают авторские параметры; новая игра начинает с пустых коллекций.
- Не хранить runtime-изменения в общей `DEF_NpcArchetype`, `.dialogue`, Blackboard или UI. Не дублировать теги/значения одновременно в ctx и агрегате как две изменяемые истины.
- API `set_val/get_val` поддерживает произвольный Variant. Для сохранения использовать существующий codec и явно поддерживаемые им данные; live Node/Entity/Object/RID не превращать в долговременную ссылку. Непредставимое значение должно давать понятную ошибку preflight до записи, а не молча становиться строкой/`null` или теряться.
- Включить коллекции в `SAVE_FIELDS`/snapshot validation; проверить поддерживаемые составные значения. При изменении схемы версионировать её по текущему проектному контракту; старые пользовательские файлы не перезаписывать ради проверки.
- Общие параметры не заменяют авторитет денег, HP, заказа, отношений или `NpcMemory`. Например, `set_tag("holds_grudge")` — авторский флаг, который не переписывает социальную память и результат настоящего `holds_grudge()`.
- Закрытый/инвалидированный ctx не выполняет запоздалую запись. Сохранить modal focus, lifetime-проверки после await и `DialogueResourceLifecycle.release_runtime_references()`.
- Защитить один выбор/шаг от технического двойного исполнения. Новый осознанный выбор игрока может снова вызвать `add_val()`; не делать прибавление навсегда одноразовым по имени ключа.

## Авторский пример для будущей реализации

Пример исправляет инверсию первого знакомства из грубого наброска: новый игрок проходит ветку `not visited`. `remember_gift` — учёт уже подтверждённой передачи 10 монет, не само списание денег.

```text
~ greeting
if not ctx.get_tag("visited")
    $> ctx.set_tag("visited")
    {{ctx.speaker_name()}}: Привет, новичок...
else
    {{ctx.speaker_name()}}: А, это ты...
=> END

~ remember_gift
$> ctx.add_val("taked_money", 10)
if ctx.get_val("taked_money") > 300
    {{ctx.speaker_name()}}: О! Мой любимый спонсор!
else
    {{ctx.speaker_name()}}: Спасибо.
=> END
```

В произвольной ветке до первого `set_val/add_val` проверять `get_val(...) != null` перед числовым сравнением. Этот пример пока не компилировался и не добавлен в игровые диалоги.

- Повторный `set_tag` безопасен; `set_val` сохраняет тип int/float/bool/String/Array/Dictionary и других Variant; явный null остаётся заданным null, чтение ничего не дописывает.

- Поддерживаемые значения проходят round-trip; некодируемые значения выявляются до замены сохранения. Прерванный ctx и повторный callback не выполняют лишний счётчик/платёж.
- `holds_grudge()` сохраняет действующую семантику, special cues/response tags и ресурсный cleanup остаются корректны.
