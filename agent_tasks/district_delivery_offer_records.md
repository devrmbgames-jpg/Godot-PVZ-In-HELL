# Доставка — постоянные предложения и ежедневный выбор

Status: **PLANNED**

Родительский этап: [Терминал и доставка](district_terminal_delivery.md). Порядок выполнения: [общая задача](district_service_update.md).

Зависимости: [Посылки — записи поступления и ручная потеря](district_package_receipts_loss.md).

## Task state

### Goal

Создать устойчивую модель предложений/обязательств доставки и ежедневный выбор реальных заказов без повторных бросков.

### Current

Расширение существующей домашней доставки ещё не начато. Это задача данных и доменных операций; UI и диалоги подключаются следующими задачами.

### Validation

Эта выделенная задача ещё не прошла приёмку. Ранее выполненные проверки в Current или родительском файле — контрольные точки; новые проверки записывать только после фактического запуска.

Parser, регрессии количества/пригодности кандидатов, повторного принятия и суточной однократности; round-trip записей без Node-ссылок.

### Owner QA / blockers

Цены и шанс личных предложений доступны в авторских ресурсах; внешний вид проверяется позже.

## Работы

- [ ] Хранить стабильные ID посылки, визита и NPC, источник TERMINAL/PERSONAL, день, срок, цену, статус, публикацию и необязательный сценарий.
- [ ] Предлагать 1–3 реальные зарегистрированные посылки живых местных жителей в день; при нехватке подходящих — меньше. Одна посылка не получает конкурирующие активные предложения.
- [ ] Фиксированную доплату терминала по умолчанию брать равной базовой оплате выдачи; убрать общий лимит двух принятых доставок.
- [ ] Подготовить регулируемые 10% личных предложений, тестовый минимум одного в день при наличии кандидата и сценарное назначение.
- [ ] Фиксировать ежедневный выбор, принятие/отказ и исход торга; длительная фаза, повторный разговор и загрузка не перебрасывают их. Частное предложение по умолчанию не публикуется.

## Критерии завершения

- Предложения восстанавливаются по тем же ID и не дублируются; ограничение двух принятых снято.
- Недостаток кандидатов и повторные обновления дают устойчивый корректный результат.

Выполнять только этот ограниченный результат, объединяя связанные чтения, правки и проверки. Не расширять задачу соседними функциями. Закрыть её собственные Status/Current/Validation, сохранить связный результат коммитом и обновить следующее действие в общей задаче. Завершение этой задачи само по себе не закрывает родительский этап.
