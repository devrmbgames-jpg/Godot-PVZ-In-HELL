## Task state

### Goal

Создать устойчивую модель предложений/обязательств доставки и ежедневный выбор реальных заказов без повторных бросков.

### Current

Реализованы постоянные предложения/обязательства: стабильные ID коробки, истории, визита и личности, источник, публикация, адрес, день/срок, исходная и согласованная доплата, сценарий и однократный торг. Ежедневный выбор выполняет `NpcDeliveryOfferService` при реальной регистрации или подготовке утра, без AI polling. Рассмотренные заказы и суточная цель терминала сохраняются; повторное обновление и загрузка не перебрасывают выбор.

Терминал выбирает 1–3 подходящих зарегистрированных заказа живых местных жителей. Личные предложения используют вероятность 10% и тестовый минимум одного; при нехватке кандидатов этот минимум имеет приоритет. Одна коробка получает одно предложение; отказ/срыв возвращают её к обычному обслуживанию без нового предложения той же услуги. Авторское назначение может превратить непринятое предложение в личное, сохранив его ID. Личные сведения по умолчанию частные.

Принятие/отказ по ID идемпотентны, общего лимита двух принятых доставок нет. Терминальная цена фиксирована, по умолчанию равна базовой выдаче. Личный торг +50% с шансом 50% сохраняет ответ и сумму; отдельная доплата использует согласованную цену. Непринятые предложения истекают во время сна без памяти о нарушенном обещании. Встреча у двери остаётся у существующего сервиса и живых Relationships. UI и новые диалоговые ветки подключаются следующими задачами; этап 2 остаётся открытым.
