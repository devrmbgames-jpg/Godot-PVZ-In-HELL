## Task state

### Goal

Подключить сохраняемые заметки и описание жалоб к стабильной истории посылки, сохранив ввод при обновлении UI.

### Current

Примечание хранится в PackageRegistrationRecord.note, сервис обновляет его только по history_id. UI отправляет запросы note_changed, сохраняет незавершённый ввод до смены выбора/закрытия и не переписывает неизменный TextEdit при refresh. Положение курсора и прокрутка сохраняются отдельно для каждой истории; выделение и Undo сохраняются при обновлении выбранной записи. Клавиша взаимодействия не закрывает терминал во время ввода. Выход из SceneTree не пытается освобождать уже отключённый GUI-фокус.

Жалоба хранит customer_id, снимок имени и авторского текста; DEF_Customer.complaint_text позволяет задать резкую реплику, иначе используется обычная формулировка по причине. Runtime-пути подачи жалобы используют CustomerFlowService.create_complaint для имени постоянной личности; расчёт и однократность остаются у CustomerOutcomeService. Терминал показывает известные имя, текст, причину, статус и фактический штраф, в том числе 0 и ранее оплаченную потерю. Исчезновение тела/метаданных каталога не скрывает известную жалобу. Изменение жалобы обновляет панель через производную подпись.

RichTextLabel отображает обращения буквально с отключённым BBCode. Скрытые физические повреждения остаются только в debug. TerminalDeliveryInfo — временное представление адреса, доплаты и срока с published=false по умолчанию; present(..., delivery) выводит его только после явной публикации. Подключение реальных предложений принадлежит terminal_delivery_actions. В codec не добавлена новая власть: export-поля существующих записей сохраняются закрытым контрактом; DTO не сериализуется. Схема 3 остаётся отдельной задачей.
