# R25 — Документация проектных GDScript

Status: **IN_PROGRESS**

Priority: **LAST** — выполнять в последнюю очередь, после ранее поставленных игровых задач и исправлений по их QA. Эта задача не отменяет предыдущие.

## Task state

### Goal

Задокументировать все проектные `.gd` для разработчиков: краткие русские `##`-комментарии объясняют ответственность, контракты и намерения. Смысловые блоки организовать регионами `#region` / `#endregion`.

### Constraints / acceptance

- Только документация и маркеры регионов. Не менять исполняемый код, архитектуру, публичные API, аннотации, типы, имена, порядок исполнения, сцены, ресурсы и зависимости.
- Имена классов, методов, типов, сигналов и свойств оставить на английском без переименования.
- Охват: все проектные `.gd`, включая значимые вспомогательные и тестовые скрипты. Генерируемые файлы и сторонний/vendor-код исключить. `addons/` не изменять; возможные явно проектные скрипты внутри сначала установить по фактическому владельцу и действующим ограничениям репозитория.
- Для значимого скрипта/класса описать назначение и границу ответственности. Для публичного API, сигналов и важных exports — условия использования, единицы/диапазоны, результат и существенные побочные эффекты, когда это нельзя понять из имени и типов.
- Описать нетривиальные lifecycle/ownership, GECS-контракты и границы физической синхронизации. Комментарии должны отражать существующее поведение, а не задавать новую архитектуру.
- Использовать русские документируемые комментарии `##`; существующие полезные англоязычные комментарии переводить и уточнять в рамках выбранной подсистемы. Технические идентификаторы сохранять.
- Регионы применять к осмысленным блокам API, lifecycle и внутренней реализации; не переставлять код ради группировки и не добавлять пустые/избыточные регионы в маленькие скрипты.
- Не комментировать очевидный код ради покрытия. Не пересказывать реализацию построчно. Подробные объяснения остаются в `content/ARCHITECTURE.md` / существующих docs; из кода при необходимости давать короткую ссылку.
- Сохранять все посторонние пользовательские изменения. `master` — только чтение. Обычная база разработки — `dev`; отдельную ветку использовать по явному запросу владельца.

### Decisions

Работать по одной подсистеме за раз. Для каждой: найти относящиеся `.gd` и прямые контракты; читать только необходимый контекст; добавить краткие `##` и осмысленные регионы; независимо перечитать diff и удалить лишнее; выполнить лёгкую проверку; commit завершённой подсистемы отдельно.

Примеры commit: `docs: document customer scripts`, `docs: document interaction scripts`. Общую массовую правку всего репозитория и параллельное переписывание подсистем не выполнять.

Проверка ограничена изменёнными файлами: diff, отсутствие случайных изменений значимых токенов GDScript, formatter/структурная проверка при наличии инструмента. Проверка должна различать комментарии и `#` внутри строк. Игру, GUT, smoke и экспорт не запускать после документирования каждой подсистемы; документация сама по себе не требует игрового прогона.

### Validation

Для каждого этапа: utils/verify_gdscript_nonbehavior_changes.py --mode comments сравнивает исполняемые строки, отступы и точное содержимое строковых литералов с коммитом до правок. Затем Godot parser для изменённых .gd, diff/whitespace и структура. Игру, GUT, smoke и экспорт для комментариев не запускать. Данные NPC: 24 скрипта, сравнение кода PASS, Godot parser 24/24 без ошибок и предупреждений, git diff --check PASS; лог .bin/r25-npc-data-parser.log.

Исполнение NPC: 22 скрипта, сравнение кода PASS, parser 22/22 без GDScript-ошибок и предупреждений; .bin/r25-npc-runtime-parser.log. Структура и whitespace PASS. MCP использован для записи/точечных правок; его известное ложное предупреждение class_name проверено штатным parser по настоящим путям. Автопроверка отклонила полную запись двух файлов; доказано совпадение кода и применены безопасные точечные изменения только комментариев. Блокировки нет.
