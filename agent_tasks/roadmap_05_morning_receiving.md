# R05 — Утренняя поставка и состав посылок

Status: planned

Ветка/base: зафиксировать при начале реализации.
Источники: [ТЗ 00](../docs/roadmap/00_prototype_overview.md), [ТЗ 04](../docs/roadmap/04_morning_package_receiving.md), [ТЗ 17](../docs/roadmap/17_vertical_slice_scenario.md).

## Цель

Создавать воспроизводимую утреннюю поставку из 6–10 физических посылок для ручной организации.

## Начать здесь

- [content/entities/props/box.tscn](../content/entities/props/box.tscn)
- [content/scenes/main_level.tscn](../content/scenes/main_level.tscn)

Затем прочитать контракты, созданные задачами-зависимостями. Имена новых типов из roadmap — проектируемые контракты, а не утверждение о существующих файлах.

## Работы

- [ ] Создать data-driven состав поставки с адресатами, стабильными ID, описаниями и сочетаниями тегов.
- [ ] Добавить зону приёмки и безопасное физическое появление коробок без пересечения коллайдеров.
- [ ] Вызывать создание ровно один раз на Morning; различать базовую поставку и будущую PendingDelivery.
- [ ] Настроить массы/carry-профили по данным, сохранив возможность лёгкой и тяжёлой посылки.
- [ ] Оставлять положение посылок результатом действий игрока.

## Критерии готовности

- Morning создаёт 6–10 Package, включая Normal/Fragile/Heavy/Liquid и опасное содержимое.
- Повторное событие Morning не дублирует поставку; посылки свободно переносятся и не раскладываются автоматически.

## Проверки

GUT: состав, исходные состояния, повторный вход; физический smoke зоны приёмки. Общие команды и правила завершения — в [README](README.md).

## Границы

Регистрация — задача 06; реальные эффекты тегов и содержимого — 08–09. Сохранять Godot physics authority, GECS data/behavior boundaries и read-only addons. Выполненные основания переиспользовать, а не создавать заново.

Проверить завершение зависимостей по task_history.md и существующим контрактам, затем прочитать указанные исходники и актуализировать WORK.md/CURRENT_WORK.md. При реализации не считать непроверенные пункты выполненными.
