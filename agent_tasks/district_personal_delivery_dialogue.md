# Диалоги — личная доставка, торг и ловушка

Status: **IN_PROGRESS**

Родительский этап: [Терминал и доставка](district_terminal_delivery.md). Порядок выполнения: [общая задача](district_service_update.md).

Зависимости: [Доставка — постоянные предложения и ежедневный выбор](district_delivery_offer_records.md).

## Task state

### Goal

Добавить личное предложение доставки с однократным торгом и один воспроизводимый авторский сценарий ловушки.

### Current

Подключаются сохранённые предложения и однократный торг к обоим контекстам. Личная реакция на срыв выбирается один раз, применяется при следующем разговоре. Ловушка — отдельное поддерево перед обслуживанием:

```text
Dynamic Sequence
├─ Домашняя встреча с активным авторским сценарием
├─ NPC дошёл до адреса
├─ Игрок виден
├─ Игрок в радиусе ловушки
├─ Закрыть разговор и освободить ввод
└─ Запросить бой и зафиксировать сорванную встречу
```

Опасности и существующий бой сохраняют общий приоритет. Сценарий включается авторским ресурсом/тестовым override, не раскрываясь терминалу.

### Validation

Эта выделенная задача ещё не прошла приёмку. Ранее выполненные проверки в Current или родительском файле — контрольные точки; новые проверки записывать только после фактического запуска.

Импорт изменённых диалогов, parser контекстов и узкие проверки повторного торга, сценарной встречи и закрытия разговора при атаке.

### Owner QA / blockers

Владелец позднее оценивает понятность цены и реакции NPC.

Применять по области: [dialogue-systems](../.agents/skills/dialogue-systems/SKILL.md), [dialogue-manager-v4.1](../.agents/skills/dialogue-manager-v4.1/SKILL.md), [limboai-v1.8](../.agents/skills/limboai-v1.8/SKILL.md).

## Работы

- [ ] Подключить личные предложения с регулируемой вероятностью, дневным тестовым минимумом и сценарным override; повторный диалог не перебрасывает выбор.
- [ ] Дать согласие, отказ и один запрос +50%; стартовая вероятность согласия 50% задаётся ресурсом. Сохранить исход и согласованную цену.
- [ ] Частная договорённость по умолчанию не передаёт адрес терминалу и не создаёт системный штраф.
- [ ] Срыв обещания должен вызывать значимую личную память и дальнейшую реакцию по характеру через игровой сервис.
- [ ] Добавить одну авторскую ловушку с принудительным тестовым включением; скрытый сценарий не раскрывать, разговор закрывать перед боем. Не скрывать выбор боя в листе BT.

## Критерии завершения

- Торг можно выполнить один раз; загрузка и повторный разговор не меняют исход.
- Ловушка воспроизводима, а частная договорённость остаётся частной. Отказ сохраняет обычное получение.

Выполнять только этот ограниченный результат, объединяя связанные чтения, правки и проверки. Не расширять задачу соседними функциями. Закрыть её собственные Status/Current/Validation, сохранить связный результат коммитом и обновить следующее действие в общей задаче. Завершение этой задачи само по себе не закрывает родительский этап.
