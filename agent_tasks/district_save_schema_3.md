# Сохранение — схема 3 и повтор ночной записи

Status: **PLANNED**

Родительский этап: [Утренняя машина](district_morning_truck.md). Порядок выполнения: [общая задача](district_service_update.md).

Зависимости: [Машина — возвраты, дешёвая продажа и утилизация](district_truck_returns_resale.md).

## Task state

### Goal

Проверить согласованный снимок новых подсистем и повысить формат сохранения до 3 без миграции и удаления старого файла.

### Current

Каждая предыдущая задача сохраняет введённые ею данные. Здесь завершается общий контракт, а не откладывается до конца всё сохранение.

### Validation

Эта выделенная задача ещё не прошла приёмку. Ранее выполненные проверки в Current или родительском файле — контрольные точки; новые проверки записывать только после фактического запуска.

Parser, профильные GUT persistence и ограниченный round-trip/headless сценарий ошибки и повторной записи. Общий многодневный smoke выполняется в финальной задаче.

### Owner QA / blockers

Владелец позднее проверяет сообщение о несовместимом файле и продолжение нового сохранения.

## Работы

- [ ] Сверить snapshot поступлений, заметок, жалоб/уведомлений, предложений и цены торга, ожидающего дропа, мебели, партии машины и операций продажи.
- [ ] Сохранить отсутствующих/погибших постоянных NPC и согласованное размещение; Node, Blackboard и кеши восприятия не сериализовать.
- [ ] Проверить повтор ночного перехода/ошибку записи: не повторяются выплаты, последствия обещаний, коробки, жители и заселение.
- [ ] Установить схему 3; версию 2 и иные несовместимые форматы отклонять понятным сообщением, без миграции и удаления исходного файла.
- [ ] Проверить восстановление в новой сессии, а не только encode/decode одного объекта.

## Критерии завершения

- Схема 3 восстанавливает согласованный мир без дубликатов.
- Несовместимое сохранение остаётся на диске; повтор ночной записи не повторяет доменные операции.

Выполнять только этот ограниченный результат, объединяя связанные чтения, правки и проверки. Не расширять задачу соседними функциями. Закрыть её собственные Status/Current/Validation, сохранить связный результат коммитом и обновить следующее действие в общей задаче. Завершение этой задачи само по себе не закрывает родительский этап.
