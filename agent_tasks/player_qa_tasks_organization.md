# Организация задач игрового QA в qa_tasks

Status: **PLANNED**

## Task state

### Goal
Создать папку `qa_tasks/` в корне проекта и собрать в ней все ожидающие ручные проверки, которые будут выполнять непосредственно игроки.

### Constraints / acceptance
- Найти ожидающие проверки игрового/визуального QA в общих задачах `agent_tasks`, включая задачи со статусом `OWNER_QA`, чек-листы основной сцены и связанные документы с ручной приёмкой.
- Перенести в `qa_tasks/` сами задания игрокам; в задачах разработки оставить ссылки на соответствующие проверки и краткое состояние приёмки.
- Исправления кода и реализация механик остаются в задачах разработки. Например, QA-01–QA-13 описывают работу разработчика; в `qa_tasks/` нужны связанные сценарии проверки её результата игроком.
- Автоматические GUT/smoke/static проверки и уже зафиксированная историческая валидация сохраняют текущих владельцев и расположение.
- Сохранить незакрытые пункты, известные ограничения и существующие результаты. Не помечать проверку пройденной при переносе.
- Одна ручная проверка имеет один актуальный чек-лист; исходные задачи ссылаются на него, а не содержат расходящиеся копии.

### Milestones

- [ ] Создать `qa_tasks/README.md`: очередь проверок, правила запуска и записи результата, ссылки на сценарии.
- [ ] Перенести/оформить сценарии по механикам и основной сцене с обратными ссылками на задачи разработки.

### Decisions
`agent_tasks/` отвечает за выполнение разработки; `qa_tasks/` — за задания и результаты ручного тестирования игроками. Состояние ручной проверки ведётся в её QA-документе, а статус задачи разработки учитывает этот результат через ссылку.

### Current
Записана новая задача по просьбе владельца. Папка и перенос пока ожидают выполнения. Первый шаг: инвентаризировать ожидающие ручные проверки из общих задач, начиная с `OWNER_QA` и R23.

### Validation
На этапе записи требуется проверить структуру task-документа и ссылки. Проверка полноты переноса и удобства сценариев выполняется при реализации.

### Owner QA / blockers
При завершении игрок может открыть `qa_tasks/README.md`, выбрать готовый сценарий и выполнить его без поиска задания среди планов разработки. Блокеров при записи задачи нет.

## Формат задания игроку

Каждый сценарий содержит:

- название и ссылку на исходную задачу;
- состояние готовности к проверке, сцену/сборку и необходимые начальные условия;
- последовательность действий игрока простым языком;
- ожидаемый результат каждого проверяемого поведения;
- известные ограничения и зависимости, если механика ещё не готова;
- место для результата: дата, проверенная версия, пройдено/ошибка, описание и шаги воспроизведения проблемы.

Игровые инструкции должны объяснять, что сделать и увидеть. Техническая автоматическая проверка сама по себе не закрывает ручную приёмку игроком.

## Критерии готовности

- `qa_tasks/` содержит все ожидающие задания для непосредственного тестирования игроками, найденные при инвентаризации.
- В README видно, какие сценарии уже можно проверять, а какие ожидают реализации механик.
- Общие задачи ссылаются на QA-сценарии; прежние незакрытые проверки и результаты не потеряны.
- Ссылки исправны, один и тот же сценарий не ведётся независимо в нескольких местах.
