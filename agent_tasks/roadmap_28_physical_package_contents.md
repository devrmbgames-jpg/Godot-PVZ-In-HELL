# R28 — Физическое содержимое и пустые посылки

Status: **OWNER_QA**

## Task state

### Goal

Аптечки, хлеб и другое содержимое — RigidBody3D, высыпаются при распаковке; коробка становится пустой, эффекты переходят на содержимое.

### Design plan

Опыт игрока: коробка действительно содержит вещи; распаковка имеет физические и игровые последствия. Опоры: материальность предметов, читаемая причина эффекта, однократность извлечения.

Цикл: открыть коробку → содержимое высыпается и становится доступным → игрок подбирает/использует либо избегает опасного предмета → остаётся пустая переносимая упаковка. Решение игрока: выдать запечатанную посылку или принять риск вскрытия/осмотра.

1. Малый milestone: аптечка/хлеб и остальные inventory pickups как RigidBody3D, корректная заморозка/отключение коллизий в инвентаре.
2. По таблице текущих DEF_Package определить content prefab для каждого типа (книги, реагенты, оборудование, стекло, масло, ячейки, одежда, инструменты и тестовые коробки). Существующие эффекты использовать через их текущих владельцев, без параллельной системы урона.
3. Однократное извлечение: безопасный spawn/ejection; успешная распаковка нейтрализует эффекты оболочки, физическое содержимое сохраняет соответствующий эффект. Не терять товары при отказе/осмотре или повторном событии.
4. Регрессия упаковки/осмотра/опасностей один раз на завершённом крупном milestone, затем Windows build.

Риски: эффект остаётся привязан к пустой коробке; повторные спавны; содержимое теряется в полу; опасности чужой посылки дублируются при осмотре. Параметры: количество, prefab, высота/скорость выброса, сила/радиус существующего эффекта.

Гипотеза QA: игрок видит и может поднять все извлечённые предметы; пустая токсичная/взрывоопасная коробка безопасна, а соответствующий извлечённый предмет опасен.

### Constraints / acceptance

- Для каждого существующего игрового типа посылки создать хотя бы физический placeholder с соответствующим эффектом, в том числе токсичный. Состав и эффекты настраиваются ресурсами.
- Пустая коробка не наносит исходный урон/токсичность/взрыв и не генерирует содержимое повторно. Сохранить учёт отправления и отметку распаковки.
- Реальное содержимое сохраняет свои эффекты после извлечения, доступно для захвата/еды/аптечки по типу. Не менять addons, preserve authored IDs and unrelated edits.
- Учесть осмотр клиентом в кабинке, удаление/отказ и сохранение физического владения через Relationships.
- Dev only; master read-only. R25 документация выполняется последней.
