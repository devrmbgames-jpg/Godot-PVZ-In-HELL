# R27 — Клиенты строго по одному

Status: **OWNER_QA**

## Task state

### Goal

Одновременно обслуживается один клиент; следующий приходит после фактического ухода или смерти предыдущего.

### Design plan

Опыт игрока: один понятный собеседник и один активный заказ. Опоры: читаемость обслуживания, предсказуемый ритм, сохранение последствий.

Цикл: клиент входит → игрок обслуживает/проваливает → клиент осматривает или уходит → фактическое удаление → пауза → следующий визит. Опасный момент — освобождение очереди по бухгалтерскому исходу, пока NPC ещё в помещении; проверка должна удерживать слот во всех физических фазах.

1. Проверить существующее расписание и debug-команды на единый шлюз появления.
2. Подтвердить все фазы присутствия и завершённый accounting outcome целевой регрессией; исправлять только найденный обход.
3. Проверить следующий визит после ухода, документировать player QA. Настраиваемый параметр — arrival_interval_seconds; лимит клиентов всегда один.

Гипотеза QA: в помещении нет двух клиентов одновременно, следующий не пропадает из плана и не приходит во время осмотра предыдущего.

### Constraints / acceptance

- Приход ограничивает живое присутствие клиента, включая осмотр в кабинке, агрессию и уход до конечной точки. Не считать передачу коробки освобождением очереди.
- Сохранить расписания, регистрации, интервалы и диагностические команды; не потерять ожидающие визиты.
- Dev only; master read-only. R25 документация выполняется последней.
