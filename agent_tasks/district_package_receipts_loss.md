## Task state

### Goal

Сохранить известную посылку в учёте до регистрации и после уничтожения коробки; только игрок может объявить её потерянной.

### Current

Реальная поставка записывает поступление с received_day, package_id и history_id, без регистрации и номера выдачи. Сканер обновляет тот же ресурс. Терминал, поиск, сортировка и история читают постоянный журнал; отсутствие коробки строку не удаляет. До сканирования показывается «Без номера», LOST доступен до начала визита. CustomerVisit остаётся владельцем заявления; ранняя потеря закрывает будущий приход без выдуманной выдачи или отказа. TAKEN/REFUSED сохраняют прежние проверки.

Удалено автоматическое mark_missed_registration_lost. Просрочка хранится в registration_overdue_day, штраф — отдельной идемпотентной операцией и полями registration_penalty_committed / registration_penalty_day / registration_money_delta. Коробка и заказ сохраняются; поздняя регистрация допускает обычное обслуживание и оплату. При последующем ручном LOST взысканная просрочка покрывает штраф потери: доплачивается только положительный остаток. Обработанные просрочки пропускаются до поиска тела; lookup использует уже известный журнал без повторного запроса World.

Для разгрузки подготовлен CustomerFlowService.package_declared_lost(package_id): только явное заявление игрока. Повтор поставки известного package_id не создаёт вторую коробку даже после исчезновения тела. Export-поля поддерживаются текущим закрытым SaveDataCodec; новых типов и миграции нет. Схема 3 остаётся отдельной задачей.
